## 3. 증강 = 초능력: 단일 시스템

1. **게임 시작 시** 전원 각자 동일 희귀도 선택 풀에서 3개 중 1개 선택한다.
2. **개인 정상 턴 2회 완료마다** 해당 플레이어에게 증강 3개를 제시하고 1개 선택할 기회를 부여한다. 보너스 던지기나 별도 추가 턴은 개인 정상 턴을 증가시키지 않는다.
3. **게임당 증강 최대 획득 6개**를 이번 v3의 우선 해석으로 사용한다: 시작 1개 + 개인 2·4·6·8·10턴 완료 때 5개. 10턴 이후 신규 증강 지급은 중단한다. **이것은 '6개까지 줘도 될 듯'이라는 발언을 구현하기 위한 잠정 해석**으로, 사용자가 '보유 한도 6개 + 교체'를 원하면 해당 정책을 변경해야 한다. 이를 config로 분리하고 Claude가 임의로 교체 룰을 추가하지 않는다.
4. 패시브는 획득 후 해당 효과 규칙에 따라 자동 발동한다. 액티브는 소유한 증강에 정해진 사용 횟수/사용 타이밍에 따라 발동한다. 대혼란형 증강은 광역 영향이 있더라도 소유 증강으로 관리한다.
5. **별도 초능력 카드 지급·손패 최대 2장·턴당 초능력 카드 1장 제한은 폐기한다.** 다만 획득한 액티브 증강을 열람·발동·소진 여부를 표시할 수 있어야 한다.
6. 기존 `게임 시작/전체 4턴/전체 9턴에만 3회 선택` 규칙은 폐기한다.
7. 유사·동일 효과의 증강이 108개 중 존재하므로 활성화/비활성화 및 중복 정책은 데이터로 설정 가능하게 한다. 개인별 동일 증강 중복 획득은 우선 금지하고, **다른 플레이어 간 중복 금지**는 기존 초안 제안이지만 108개 전체·동시 제시 개수와의 정합성을 검토해야 하므로 구현 전 별도 확정한다.
8. 3개 선택지의 등급은 해당 **동시 선택 세션** 내에서 일치시키고, 다른 플레이어의 개인 턴 완료 시각이 다르면 동일 등급/동시 정지 강제 여부는 별도 정책으로 정의한다. 이전 '모두 동시에 선택'과 개인별 2턴 획득이 충돌하므로 클라이언트만으로 임의 해결하지 않는다.
9. 선택 제한시간은 잠정 20초, 미선택 시 서버 자동 선택. 리롤 사용 시간과 네트워크 지연 처리 규칙은 테스트로 확정한다.

## 4. 리롤 — 엄격한 단독 꼴찌 조건

- 매 증강 선택 시 **기본 리롤 1회**.
- 선택 시작 시점의 서버 점수 스냅샷 기준, 자신을 제외한 **모든 플레이어**보다 **각각 1점 이상 뒤져야만** 리롤을 추가로 **1회** 지급한다.
- 4인 기준 `eligible = otherPlayers.every(other => myScore <= other.score - 1)`.
- **공동 꼴찌, 단 한 명과 동점, 1명에게라도 앞선 경우: 추가 리롤 없음.**
- 예시: `[10, 9, 8, 7]`이면 7점 1명만 추가 1회; `[10, 9, 8, 8]`이면 없음; `[5, 5, 5, 4]`이면 4점 1명 추가.
- 점수 산식은 **미확정**이다. 골인 수만 쓸지, 이동 진척도까지 합칠지, 정수 1점 단위를 무엇으로 볼지 합의 전까지 점수 산식을 임의 제작하지 않는다. 서버에 단일 `getStandingsScore` 인터페이스로 격리한다.
- 추가 리롤은 해당 증강 선택 세션에서만 유효하고 이월하지 않는다. '리롤하면 3장 전부 갱신'을 잠정 UX/서버 기본안으로 제시하되 확정 전 임의 변경 금지.

## 5. 자동 대혼란 이벤트

- 별도의 **E1~E8 이벤트**만 자동 이벤트 추첨에 포함한다.
- 전원 **정상 턴 4·8·12·16...회 완료** 시 자동으로 1개 추첨·발동한다. 윷·모·잡기 추가 던지기는 라운드에 포함하지 않는다.
- 동일 완료 회차의 마지막 턴이 끝나는 순간, 서버는 우선 승리 여부를 확인하고 **게임이 계속될 때만** 이벤트를 발동한다.
- 개인의 4·8턴 종료 증강 선택이 자동 이벤트와 겹칠 때 **정확한 서버 처리 순서**(선택→이벤트 또는 이벤트→선택)는 미확정이므로 잠정 추천은 `라운드 마감 → 자동 이벤트 → 보류된 증강 선택 → 다음 정상 턴`이다. 실제 순서 확정 전 테스트와 문서로 명시한다.
- 완료 이벤트 중복 발동 방지를 위해 `lastTriggeredEventRound` 관리.
- 판 초기화·팀 변경·소유권 교환·골인 처리 중 이벤트가 겹쳐도 골인·승리 및 상태 정합성을 훼손하지 않는다. 이미 골인한 말은 기본적으로 보호한다.

## 7. 서버 모델 및 구현 지침

서버·프론트 기술 스택은 기존 프로젝트를 확인한 후 따른다. 특정 프레임워크를 임의로 전제하지 않는다.

```ts
// 개념 예시. 프로젝트 언어와 기존 구조에 맞게 적용.
type AugmentCategory = 'PASSIVE' | 'ACTIVE' | 'CHAOS_AUGMENT';
type AugmentTier = 'SILVER' | 'GOLD' | 'PRISMATIC';
type Phase = 'WAITING' | 'SELECTING_AUGMENT' | 'PLAYING' | 'RESOLVING_EVENT' | 'FINISHED';

interface PlayerState {
  playerId: string;
  regularTurnsCompleted: number;
  augments: Array<{ id: string; chargesRemaining?: number; active: boolean }>;
  rerollsRemaining: number;
  scoreSnapshot?: number;
}
interface GameState {
  phase: Phase;
  playerStates: PlayerState[];
  roundCompleted: number;
  lastTriggeredEventRound: number;
  pendingSelections: string[];
  activeEventId?: string;
  winnerId?: string;
}
```

- 서버에서 정상 턴 종료를 단 한 번 확정한 뒤 턴 수를 증가시킨다.
- 증강 선택 후보 3개와 리롤은 서버에서 추첨·검증한다. 본인 외 플레이어의 미공개 증강 후보는 노출하지 않는다.
- 효과 적용은 `ROLL_RESULT / BEFORE_MOVE / AFTER_MOVE / BEFORE_CAPTURE / AFTER_CAPTURE / ROUND_END / GAME_END` 등 이벤트 기반 훅을 활용한다.
- 시간 초과, 중복 클릭, 네트워크 재전송은 멱등키와 서버 상태 검사로 이중 적용을 막는다.
- 보너스 던지기와 새 정상 턴의 의미를 구분한다.
- 게임 종료 이후 지급, 리롤, 이벤트, 이동, 상태 변화를 금지한다.
- 미구현·조건 불명 증강은 `disabled`로 안전하게 격리하고 '108개 모두 구현 완료'라고 표시하지 않는다.

## 8. 최소 자동 테스트

1. 시작 증강 1개 및 각 개인 2·4·6·8·10턴에 누적 6개까지만 지급.
2. 윷·모/잡기 추가 던지기와 보너스 턴은 `regularTurnsCompleted` 미증가.
3. 전원 4·8턴 완료 때 자동 이벤트 각각 1회만 발동.
4. 실제 리롤 추가 조건: 4인 점수 `[10,9,8,7]` 마지막 1명만, `[10,9,8,8]` 전원 0명.
5. 기본 리롤은 증강 선택마다 1회, 추가 1회는 단독 1점 차 이상 꼴찌일 때만.
6. 소모성 별도 초능력 카드 드로우/손패 제한이 더 이상 존재하지 않음.
7. 패시브/액티브/대혼란형 증강은 동일 소유 `augments` 컬렉션으로 관리.

12. 디자인 변경이 필요한 영역은 실제 UI 구현이 아닌 Figma AI 요청 목록으로 출력됨.

## 9. Claude Code에 대한 실행 요청

1. 기존 코드/문서를 먼저 확인하고 v2 분리형 증강·초능력 설계가 남아 있는 위치를 찾아 목록화한다.

4. **6개 = 총 획득 한도**를 잠정값으로 사용하되, 보유 교체 허용으로 해석을 바꾸지 않는다. 정책값을 설정으로 분리한다.
5. **점수 산식, 등급 출현 확률, 전체 동시 선택 vs 개인별 선택, 중복 금지 범위, 제한시간 자동 이동 우선순위**는 미확정으로 보고한다.
6. 모든 기능 구현 후에도 능력 후보 108개가 곧 활성화된 효과 108개를 뜻하지 않도록 개발 현황표를 관리한다.
7. 디자인 이슈가 생기면 `Figma AI 전달용 요청 목록`만 작성하고 사용자에게 전달한다. Claude는 디자인을 임의로 만들지 않는다.

## 부록 B. 자동 대혼란 이벤트 8개 (v2 원문 보존)

| ID | 이름 | 기본 효과 | 권장 안전조건 |
|---|---|---|---|
| E1 | 말 대이동 | 판 위 모든 말 랜덤 재배치 | 골인·대기 말 제외, 스택 처리 정책 필수 |
| E2 | 임시 동맹 | 무작위 2인씩 1라운드 팀으로 묶어 아군 잡기 차단 | **개인전 승리 조건은 그대로**, 임시 잡기 금지만 적용 |
| E3 | 뒤집힌 세계 | 1라운드 이동 방향 반전 | 모든 일반 이동에 적용, 빽도는 최종 방향 부호 한 번만 반전 |
| E4 | 황금 지름길 | 1라운드 모든 꼭짓점에서 지름길 선택 가능 | 경로 그래프에 존재하는 합법 경로만 허용 |
| E5 | 왕의 몰락 | 1위 판 위 말 1개 출발점 귀환 | 목표 말이 없으면 미발동·로그 기록 |
| E6 | 전원 출동 | 각 플레이어 대기 말 1개씩 도만큼 출발 | 대기 말이 없는 플레이어는 건너뜀 |
| E7 | 혼돈의 윷 | 1라운드 윷·모 추가 던지기 봉쇄 | 기본 결과 이동은 유지, 증강 추가 던지기와 구분 |
| E8 | 운명의 자리 교환 | 서로 다른 플레이어 말 2쌍 위치 교환 | 대상 수 부족하면 가능한 쌍만 처리 |

- **발동 주기:** 전원 정상 턴 완료 횟수 최솟값이 `4,8,12,16...`으로 새롭게 도달할 때 한 번.
- **선택 방식:** 서버 RNG로 E1~E8 중 1개. 기본적으로 **같은 게임 내 이벤트 중복 허용**, 직전과 동일한 E는 회피하는 옵션을 권장.
- **지속시간:** 1라운드 = 다음 4명의 **정상 턴 각 1회**를 모두 완료할 때까지. 해당 시간 내 보너스 턴도 이벤트 영향은 받지만 지속시간 카운트에서는 제외.
- **이벤트 대기열:** 중첩된 지속 이벤트는 `activeGlobalEffects[]`에 보관하고 `expiresAfterRound`로 제거. 상충(정방향/역방향, 지름길 봉쇄/허용 등) 시 우선순위 표를 적용.
- **완전히 무효가 될 수 있는 이벤트:** 대상 부족 시 아무도 피해 보지 않고 이벤트 발생 기록만 남겨도 됨. 서버가 추가 이벤트를 무한 재추첨하지 않음.
