# 증강 윷놀이 — 패시브 46개 발동 횟수 밸런스 제안 v1

> Claude Code 전달용 **제안안**. 사용자 최종 승인 전에는 코드·효과·UI를 변경하지 않는다. 첨부된 `augmented_yutnori_augments_108_only(1).md`의 패시브 유형만 추출했으며, 자동 대혼란 이벤트·액티브·플레이어 획득형 대혼란 증강은 변경 대상이 아니다.

## 적용 원칙

- **패시브 전체 46개**에 `최대 발동 횟수 1~3회`를 부여한다. 수치는 **증강을 보유한 플레이어 기준, 그 증강의 전체 게임 누적 사용량**이다. 턴마다 충전하지 않는다.
- 초강력(턴 개입, 무적에 가까운 기능, 확정 윷/추가 던지기, 전체 상대 이동 제약)은 1회; 일반 이동/방어/전략 변경은 2회; 확률 효과·상대적으로 작은 이득은 3회.
- **실제 효과가 발동된 경우에만 차감**을 기본으로 한다. 조건 불충족·확률 미당첨·법적 이동 불가·효과 없이 검사만 한 경우는 차감하지 않는다. 예외적으로 `C-S14`는 '이번 잡힘 50%'이므로 1회의 시도를 소비하며 실패해도 차감하는 것을 제안한다.
- 패시브가 자동으로 발동하는 효과는 서버가 정확히 1회 차감하고, 선택형 패시브는 사용자가 보정/분할/지름길 등을 실제 선택했을 때 차감한다.
- 횟수 소진 뒤에는 효과를 적용하지 않는다. **기본 윷놀이 규칙은 그대로 적용**하며, 보유 증강 슬롯도 그대로 유지한다.
- `말당 1회`처럼 원문 자체의 제약이 있는 경우 새 전역 사용 횟수와 충돌하므로 표의 '특이사항'을 따른다. 사용자 확정이 필요한 변경이다.
- 여러 패시브가 같은 던지기/이동에 개입하면 이미 확정한 우선순위/연쇄 방지 규칙을 유지하고, **실제로 선택·성공하여 적용된 패시브만** 차감한다. 패시브의 발동 한도만 수정하며 확률/효과 자체는 변경하지 않는다.

## 구현 시 우선 확인할 설계 문제

1. **선택형 패시브**(예: 결과 보정, 분할 이동, 지름길)의 자동 발동과 차감 조건을 명확히 나눈다. 이미 소진한 패시브를 선택지·미리보기·자동 타임아웃 이동 후보에서 제거한다.
2. **확률형 패시브**는 성공할 때만 차감하는지 명확히 구현하며, 실패 시 횟수 감소가 없는지 테스트한다. 확률은 원래 명세 그대로 둔다.
3. **보호형 패시브**는 실제 방어가 성공했을 때만 소모하며, 한 번의 잡기 이벤트에서 같은 증강이 중복 소비되지 않도록 한다.
4. **전역 횟수 대 개별 말 횟수**: `A-S15`, `A-P3`는 기존 말당 제한과 전역 상한이 함께 적용되는지 사용자 최종 확인이 필요하다.
5. **게임 중 증강 교체**: 교체한 카드의 사용 횟수/예약이 삭제되고 신규 카드의 사용 가능 횟수가 초기화되도록 한다. 버렸다가 다시 얻을 때도 보유/소진 처리 정책에 일관성을 둔다.
6. **영구형 지속 효과 소모 시점**: `O-P7`은 상대의 지름길을 막거나 내 지름길을 허용할 때 정확히 몇 번 소비하는지, `O-S5`/`O-G10`은 방어가 성공하는 순간에만 차감하는지 명시한 뒤 테스트한다.
7. **UI**: 하단 패시브 카드에 남은 횟수, 소진 상태를 보여주는 새 UI가 필요할 수 있다. 기존 PNG 기반 화면을 임의로 재설계하지 말고 현행 카드 구조로 표시 가능한지 먼저 확인하고, 추가 디자인 결정만 사용자에게 질문한다.
8. **안전성 테스트**: 46개 ID 매핑 누락 없음, 0회 후 재발동 금지, 액티브와 패시브 횟수 저장 분리, 확률/중복, 재접속, 턴 타임아웃, 이벤트와 겹침, 증강 교체, 게임 종료 후 재시작까지 검사한다.

## Claude Code에 전달할 실행 지시

1. 우선 본 표의 46개 ID 및 횟수 규칙을 실제 `augment.ts`, `effects.ts`, `play.ts`, `turn.ts`, 기타 능력 처리와 대조해 **적용 가능/모호/원문 충돌** 표를 먼저 작성한다.
