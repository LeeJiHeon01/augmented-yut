# 증강 윷놀이 — Claude Code 개발 명세서 v2

작성일: 2026-10-24  
상태: **개발용 규칙 기준안 / 개별 효과 밸런스 및 위험 기능은 미확정**  
기준: 기존 `augmented_yutnori_claude_spec.md`의 증강 후보 108개와 이벤트 8개를 **삭제 없이 보존·재분류**.

## 0. 변경 요약 및 수량

- **개인 턴 2회 완료마다 초능력 카드 1장 지급**. 자신의 2·4·6·8·10…번째 정상 턴이 끝날 때 지급한다. 보너스 던지기는 턴 수에 포함되지 않는다.
- **전원 개인 4턴 완료마다 대혼란 이벤트 1회**. 다시 말해 4인 게임의 전원 4·8·12…번째 정상 턴 종료 후 발동한다.
- 이전의 **시작 / 전원 4턴 후 / 전원 9턴 후 증강 선택 3회는 유지**한다. 지속 증강 선택과 소모성 초능력 카드는 별도 시스템이다.
- 플레이어당 카드 **최대 2장 보유**, 자신의 정상 턴에 **최대 1장 사용**. 상황에 따라 반응형 사용이 필요한 능력은 별도 예약 UI/발동 창으로 처리.
- 기존 '대혼란' 분류 후보는 전체 판에 영향을 줄 수 있는 **대혼란형 능력 후보**이지, 자동 이벤트 8종에 추가된 것이 아니다. 자동 이벤트는 **E1~E8만** 사용한다.
- 실버/골드/프리즘은 **희귀도**, 패시브/액티브/대혼란은 **효과 처리 방식**이다. 서로 독립된 속성이다.

|---|---:|---:|---:|---:|
| 최초 초안 O | 15 | 13 | 8 | 36 |
| GPT 1차 A | 15 | 13 | 8 | 36 |

**총 116개 아이디어**이며 중복·유사 능력을 정리한 출시 카드 수를 뜻하지 않는다.

### 효과 방식별 재분류 집계

| 희귀도 | 패시브 | 액티브 | 대혼란형 후보 | 합계 |
|---|---:|---:|---:|---:|
| 실버 | 27 | 16 | 2 | 45 |
| 골드 | 15 | 22 | 2 | 39 |
| 프리즘 | 4 | 15 | 5 | 24 |
| **합계** | **46** | **53** | **9** | **108** |

> 집계 기준: 기존 `유형`은 최대한 존중하고, 전원/판 전체 상태를 대규모로 바꾸는 아홉 후보를 대혼란형으로 재분류했다. 이는 밸런스 검증 전 **기본 추천 분류**이며 자동 이벤트로 편입했다는 의미가 아니다. 대혼란형 후보도 소모성 초능력 카드로 쓸 수 있지만, MVP에서는 `disabled`로 시작하는 편이 안전하다.

## 1. 용어 및 게임 기본값

| 용어 | 정의 |
|---|---|
| 개인 정상 턴 | 현재 플레이어에게 기본 순서로 부여된 정규 차례 1회. 윷·모·잡기 추가 던지기는 그 턴 안에 포함 |
| 개인 턴 수 `regularTurnsCompleted[playerId]` | 그 플레이어의 **정상 턴이 최종 종료**할 때만 +1. 패스한 정상 턴도 1회로 계산 |
| 전원 완료 회차 `completedRound` | 모든 참가자의 정상 턴 완료 횟수 최솟값 (`min(regularTurnsCompleted)`) |
| 초능력 카드 | 2턴마다 받는 **소모성 카드**. 기본 액티브/대혼란 후보에서 추출. 패시브는 이 풀에 넣지 않음 |
| 증강 | 3회 선택하여 보유하는 **지속/횟수제 능력**. 패시브 중심, 선택형 액티브도 가능 |
| 자동 대혼란 이벤트 | 개인 소유물이 아닌 E1~E8 중 하나가 4회차마다 서버에서 자동 발동 |
| 라운드 | 4인 모두 정상 턴을 한 번씩 끝내면 증가하는 전원 완료 회차. 실제 턴 순서/추가 턴과 분리 |

**보유 및 사용 기본값:** 카드 보유 상한 2장, 자신의 정상 턴마다 액티브 초능력 카드 최대 1장. 사용 가능 창은 `TURN_START`(윷 던지기 전), `POST_ROLL`(결과 확정 전), `PRE_MOVE`(말 이동 선택 전), `REACTIVE`(공격·잡기 직전 반응) 등 카드별로 별도 지정. 일반 카드 사용은 **자기 턴**만 허용한다. 반응형은 사용자 확인 지연을 피하도록 '자기 턴에 1회 방어 예약, 조건 시 자동 발동'으로 구현 권장. 예약도 카드 사용량 1회 소비로 센다.

## 2. 턴 순서·지급·자동 이벤트 규칙 (확정 기본값)

1. 방/플레이어 확정 후 게임 시작. 모든 플레이어가 **증강 3개 중 1개**를 선택한다. 여기서는 기본 실버 등급.
2. 각 정상 턴: `TURN_START → 초능력 사용(선택) → 윷 던지기 → 결과 보정 → 말 이동/잡기/골인 → 추가 던지기 처리 → TURN_END`.
3. 자기 정상 턴이 최종 종료될 때 `regularTurnsCompleted[p] += 1`.
4. 해당 플레이어 턴 수가 **2의 배수**이면 초능력 카드 1장 무작위 지급. 보유 카드가 이미 2장이면 서버가 드로우 보류 상태(`pendingCardDraw=1`)로 기록하고 해당 플레이어가 카드 1장을 버리거나 사용할 때 지급. **버리기/사용 선택을 강제하는 UI도 가능하나, 다른 턴 진행은 막지 않는다.** 보류 드로우는 최대 1개만 유지(넘친 드로우는 소멸·로그 남김).
5. 턴 종료로 `completedRound`가 증가하면 라운드 마감 작업을 수행. **전원 4, 8, 12, ...회차** 완료마다 자동 대혼란 이벤트 1개 발동한다.
6. **전원 4회차** 마감은 `자동 이벤트 → 2회차 증강 선택(골드 또는 프리즘) → 다음 정상 턴` 순서. **전원 9회차** 마감은 `3회차 증강 선택(골드 또는 프리즘) → 다음 정상 턴` 순서.
7. **전원 8회차**에는 자동 이벤트만; **12회차**부터 4회차 간격 반복. 4·9회차 선택 외 추가 증강 선택 없음.
8. 1위가 골인해서 게임이 종료되면 그 시점에 **즉시 종료**, 더 이상의 지급/이벤트/증강 선택은 발생하지 않는다. 이미 결과 확정 전에 발생한 이벤트는 되돌리지 않는다.
9. 효과로 추가되는 턴(`BONUS_TURN`)은 카드 지급·전원 완료 회차·증강 선택을 **진행시키지 않는다**. 추가 던지기와 추가 턴은 구분한다.

### 4인 진행 예시

| 시점 | 지급/발생 |
|---|---|
| 게임 시작 | 전원 증강 선택 1회(실버) |
| 각자 2번째 정상 턴 종료 | 해당자 초능력 카드 1장 |
| 각자 4번째 정상 턴 종료 | 해당자 초능력 카드 1장 |
| **전원 4번째 턴 종료** | **E 이벤트 1회 → 증강 선택 2회차** |
| 각자 6번째 정상 턴 종료 | 해당자 초능력 카드 1장 |
| 각자 8번째 정상 턴 종료 | 해당자 초능력 카드 1장 |
| **전원 8번째 턴 종료** | **E 이벤트 1회** |
| **전원 9번째 턴 종료** | **증강 선택 3회차** |
| 각자 10번째 정상 턴 종료 | 해당자 초능력 카드 1장 |
| **전원 12번째 턴 종료** | **E 이벤트 1회** |

같은 정상 턴 종료로 카드 지급과 이벤트 둘 다 조건을 만족하면 **개인 카드 지급을 먼저 확정하고**, 이후 **전원 이벤트**를 처리한다. 카드 지급 그 자체가 즉시 사용/추가 턴을 만들지는 않는다.

## 3. 세 분류 운영 규칙

- **패시브:** 장착 중 자동으로 발동. 기존 3회 증강 선택에서 획득. 실효성이 낮은 영구 효과와 무한 획득 보상은 별도 밸런스 플래그 검토.
- **액티브:** 플레이어가 사용을 선택하는 일회성/횟수제 능력. 기존 증강으로 획득했다면 명시된 `charges`를 지키고, 초능력 카드로 지급되면 **카드 1장당 1회 소모**. 두 방식은 `sourceKind`로 구분.
- **대혼란형:** 판 전체·다인 영향이 큰 효과 후보. 수동 카드로 쓰이는 C 카드와 **E1~E8 자동 이벤트**는 동일하지 않다. 진짜 자동 이벤트는 소유자 없이 RNG로 실행. 게임 진행을 급격히 되돌리는 후보는 기능 플래그로 비활성 가능.
- **등급:** 최초 초안의 실버·골드·프리즘은 그대로 유지. 초능력 소모 카드의 희귀도 풀은 `silver:75%, gold:23%, prism:2%`를 테스트용 초기값으로 제안(밸런스 확정 아님). 프리즘은 4라운드 이후부터만 획득 가능하도록 제한 추천. 자동 이벤트는 등급과 무관.
- **저주형:** 패시브·액티브·대혼란과 별도의 `polarity` 속성(`benefit / chaos / curse`)으로 표기한다. 강한 불이익 효과를 소모 카드에서 뽑았다면 버리거나 사용할 수 있어야 하며, **강제 사용 저주**를 의도할 경우 카드 타입을 `mandatory`로 따로 만들어야 한다. MVP에는 강제 사용 저주 없음.
- **3회 증강 선택:** 시작(실버), 전원 4턴 완료 시(골드/프리즘), 전원 9턴 완료 시(골드/프리즘). 한 게임에 프리즘 등급 선택 회차 최대 1회. 모든 플레이어 동일 등급. 3장 제시·1장 선택, 리롤 기본 1회, 선택 시 꼴찌 추가 1회. 같은 게임에서 이미 **선택 확정된** 카드만 배제하고 고갈 시 정책 적용. 선택 UI 단계는 게임 전체 일시 정지.
- **카드 드로우:** 기본적으로 1장 지급, 세 장 선택 아님. 중복 후보는 허용할 수 있으나 **같은 플레이어가 동일 ID 소모 카드를 2장 쥐는 것은 기본 금지**. 고갈 시 재섞기/가중치 기반 선택. 카드 RNG와 증강 선택 RNG는 서버 관리.

| E7 | 혼돈의 윷 | 1라운드 윷·모 추가 던지기 봉쇄 | 기본 결과 이동은 유지, 증강 추가 던지기와 구분 |
| E8 | 운명의 자리 교환 | 서로 다른 플레이어 말 2쌍 위치 교환 | 대상 수 부족하면 가능한 쌍만 처리 |

- **발동 주기:** 전원 정상 턴 완료 횟수 최솟값이 `4,8,12,16...`으로 새롭게 도달할 때 한 번.
- **선택 방식:** 서버 RNG로 E1~E8 중 1개. 기본적으로 **같은 게임 내 이벤트 중복 허용**, 직전과 동일한 E는 회피하는 옵션을 권장.
- **지속시간:** 1라운드 = 다음 4명의 **정상 턴 각 1회**를 모두 완료할 때까지. 해당 시간 내 보너스 턴도 이벤트 영향은 받지만 지속시간 카운트에서는 제외.
- **이벤트 대기열:** 중첩된 지속 이벤트는 `activeGlobalEffects[]`에 보관하고 `expiresAfterRound`로 제거. 상충(정방향/역방향, 지름길 봉쇄/허용 등) 시 우선순위 표를 적용.
- **완전히 무효가 될 수 있는 이벤트:** 대상 부족 시 아무도 피해 보지 않고 이벤트 발생 기록만 남겨도 됨. 서버가 추가 이벤트를 무한 재추첨하지 않음.

## 6. 2턴 카드 시스템 상세

### 카드 지급·보유·사용

1. 플레이어별 `regularTurnsCompleted`가 2의 배수에 도달하면 드로우 발생.
2. 받을 수 없는 상태(게임 종료/카드 2장 보유)라면 `pendingCardDraw` 1개까지 저장한다. 1개 보류 중 다음 드로우가 발생하면 새 드로우는 소멸한다.
3. 보류 카드는 다음 번 해당 플레이어가 카드 1장을 버리거나 사용하여 빈 칸이 생기면 자동 지급한다. 이렇게 자동 지급된 카드도 **그 정상 턴의 사용 한도는 증가시키지 않는다**.
4. 발동 가능 타이밍 아닌 카드 사용 시 서버에서 거절. 유효한 카드 사용이 성공한 뒤에만 소모 처리; 대상을 못 찾으면 소비하지 않고 사용자에게 알린다.
5. 사용 후 1장 소모, 같은 정규 턴에 두 번째 카드는 사용 불가. 패시브의 자동 발동은 이 사용 한도에 포함되지 않음.
6. `대혼란형` 능력 중 C-P1·C-P2·C-P8처럼 판 재편이 심한 카드들은 **별도 풀/비활성 플래그**로 제어한다.
7. 매 턴마다 카드가 추가되는 방식이 아니므로, 사용하지 않는 한 카드가 쌓여도 2장까지만 유지된다.

### 중요한 예외

- **상대 턴 인터럽트:** O-G3 저주의 빽도, 방어 반응형 등은 간단한 자기 턴 카드 UI로 처리 불가. `REACTIVE` 전용 큐 혹은 자기 턴 예약제로 별도 구현한다. 초기 버전에서는 비활성화 가능.
- **지연 결과 교환:** A-G3 운명 교환, C-S4 남의 떡은 대상 플레이어의 다음 던지기 결과가 아직 없으므로 `pendingRollSwap` 예약 상태 사용.
- **패시브와 소모 카드 겹침:** 같은 효과가 동시에 적용되어야 한다면 버프 우선순위 및 중첩 상한 적용.
- **'전원'의 의미:** 연결이 일시 끊긴 플레이어도 서버의 정규 턴 정책에 따라 기권 또는 자동 패스를 처리하여 회차가 멈추지 않도록 한다.

## 7. 서버 상태 및 데이터 모델 (권장 TypeScript 형태; 기술 스택 확정 아님)

```ts
type Rarity = 'SILVER' | 'GOLD' | 'PRISM';
type EffectMode = 'PASSIVE' | 'ACTIVE' | 'CHAOS';
type SourceKind = 'AUGMENT' | 'ABILITY_CARD' | 'GLOBAL_EVENT';
type Polarity = 'benefit' | 'chaos' | 'curse';
type EffectWindow = 'TURN_START' | 'POST_ROLL' | 'PRE_MOVE' | 'REACTIVE' | 'ROUND_END';
interface EffectDefinition {
  id: string; name: string; rarity?: Rarity; mode: EffectMode;
  polarity: Polarity; enabled: boolean; window?: EffectWindow;
  baseCharges?: number; targetScope?: 'PIECE' | 'STACK' | 'PLAYER' | 'GLOBAL';
  stackPolicy?: 'DENY' | 'STACK' | 'REPLACE';
  description: string;
}
interface PlayerState {
  id: string;
  regularTurnsCompleted: number;
  augments: string[]; // 최대 3개, 선택으로만 추가
  abilityCards: {instanceId: string; definitionId: string}[]; // 최대 2장
  pendingCardDraw: 0 | 1;
  cardUsedThisRegularTurn: boolean;
}
interface GameState {
  phase: 'AUGMENT_DRAFT' | 'TURN' | 'ROUND_EVENT' | 'GAME_OVER';
  players: PlayerState[];
  completedRound: number;
  nextGlobalEventRound: number; // 초기 4
  activeGlobalEffects: Array<{id:string; expiresAfterRound:number}>;
  pendingBonusTurns: Array<{playerId:string; origin:string}>;
  // 기존 말/보드/던지기 상태는 원래 엔진의 데이터 구조를 우선 사용
}
```

- 카드 인스턴스 ID와 효과 정의 ID를 구분해서 **카드 중복 및 소비를 추적**한다.
- 온라인 동기화는 서버-authoritative 트랜잭션/원자 이벤트 로그를 통해 구현한다.
- RNG 결과와 선택/피해 대상은 서버에서 산출하고 리플레이용 로그에 남긴다.
- 게임 종료 검사 이후의 이벤트는 큐에 넣지 않는다.

### 처리 예제 의사코드

```ts
function onRegularTurnFinished(game, playerId) {
  if (game.phase === 'GAME_OVER') return;
  const p = player(game, playerId);
  p.regularTurnsCompleted += 1;
  p.cardUsedThisRegularTurn = false;
  if (p.regularTurnsCompleted % 2 === 0) enqueueAbilityDrawOrPending(game, p);
  const newRound = Math.min(...game.players.map(x => x.regularTurnsCompleted));
  if (newRound > game.completedRound) {
    game.completedRound = newRound;
    expireRoundEffects(game, newRound); // 기간 종료부터 처리
    if (newRound % 4 === 0) resolveOneGlobalEvent(game); // 4,8,12,...
    if (newRound === 4 || newRound === 9) startAugmentDraft(game, newRound);
  }
  if (game.phase !== 'AUGMENT_DRAFT' && game.phase !== 'GAME_OVER') advanceToNextRegularTurn(game);
}
```

> 이벤트 후 증강 선택 여부는 `completedRound === 4` 분기에서 처리된다. `resolveOneGlobalEvent()`은 새로 발생한 효과를 게임 상태에 등록만 해야 하며, 다른 플레이어의 정규 턴 수를 임의로 증가시키면 안 된다. 이벤트로 즉시 승자가 생기면 **드래프트를 시작하지 않고 종료**한다.

## 8. 충돌 및 불변식 — 구현 전 필수

- `FINISHED` 말은 일반적인 위치 섞기·귀환·팀 교환·판 초기화의 대상이 아니다. 골인 말 수는 실제 말 상태에서 계산하며, 가상의 골인 카운터를 별도 수정하지 않는다.
- `WAITING / ON_BOARD / FINISHED` 말 상태는 항상 하나만 갖는다. 이동과 위치 교환은 윷판 **경로 그래프**를 따라 처리하며, 단순 좌표 덮어쓰기로 구현하지 않는다.
- 영구 소유권 변경(C-P4)과 골인 수 강제교환(C-P7)은 **초기 비활성**. 구현한다면 각자의 말 4개 보유 불변식/완주 로직을 안전하게 유지하도록 별도 설계.
- 전역 리셋 C-P1/E1/E8, 분신 O-P2, 시간 역행 O-P5는 **고난도 효과 플래그**로 구분, 기본 윷놀이가 작동한 뒤 별도 통합 테스트로 도입.
- 모든 이동/잡기/골인/추가 던지기는 공통 상태 변경 엔진을 사용. 반복 발동은 효과 스택 최대 깊이와 턴당 추가 던지기 한도로 차단(초기 예시 5회).
- 랜덤 이벤트는 동점·대상 부족·이미 잡힌 말·시작 대기 말·스택된 말에 대한 예외 로직 필수.
- **임시 팀**은 아군 잡기 금지·효과 공유에만 적용, 개인전 승리는 변하지 않는다. 이미 골인한 말이 임시 팀으로 인해 사라져서는 안 된다.
- 단계 중단(다른 사용자 UI 대기)이 발생하면 선택 시간제한 또는 서버 기본 선택 정책을 둔다.

## 9. 자동 테스트 요구사항

1. 4인 정상 턴이 한 명씩 1회일 때 completedRound=1, 2회면 각자 카드 1장, completedRound=2.
2. 한 명만 4회 완료해도 E 이벤트는 발동하지 않음. 모두 4회 완료하면 이벤트 **정확히 1회** 및 2회 증강 선택 **정확히 1회**.
3. 모두 8회 완료하면 E 이벤트가 총 2회, 모두 9회 완료 시 이벤트는 여전히 2회이지만 증강 선택 총 3회.
4. 윷/모 추가 던지기, 잡기 보너스, EXTRA_TURN 때문에 개인 `regularTurnsCompleted`가 추가 증가하지 않음.
5. 보유 2장에서 드로우 보류되고, 1장 사용 후 자동 지급되며, 동시 드로우가 카드 3장이 되지 않음.
6. 카드 사용 후 개인 정상 턴당 두 번째 카드 사용 차단; 패시브 자동 발동은 가능.
7. 서버에 존재하지 않는 카드 인스턴스·위법 대상·이미 소비한 카드의 재사용 요청은 거절.
8. 전역 이벤트 중 골인 상태 유지, 실효 대상 없는 경우에도 서버 상태 일관성 유지.
9. 첫 선택 시작/4라운드/9라운드 증강 드래프트 정확히 세 번, 프리즘 선택 회차 최대 1회.
10. 임시 팀·강제 위치 이동·분신 등 고위험 효과는 플래그 OFF 시 드로우/자동 이벤트에 섞이지 않음.
