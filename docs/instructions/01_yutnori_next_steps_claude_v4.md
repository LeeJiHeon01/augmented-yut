# 증강 윷놀이 — 다음 개발 작업 지시 v4

기준: `progress.md` 최신본, `docs/augmented_yutnori_claude_spec_v3.md`, 증강 108개 데이터.

## 원칙
- **증강과 초능력은 동일한 시스템**이다. 별도의 초능력 카드 지급 시스템을 만들지 않는다.
- Figma/PNG 디자인은 사용자가 Figma AI로 관리한다. **Claude Code는 UI를 임의로 설계하거나 수정하지 않는다.** 필요한 화면/상태는 마지막 `Figma AI 요청 목록`에 적고 승인을 받는다. 이미 승인된 PNG의 구현은 가능하다.
- 실제 코드 상태를 먼저 확인하고, 보고서에 적힌 구현 완료·테스트 통과를 재확인한다.
- 증강 108개 전체가 선택 가능하나 효과 미구현인 상태를 운영 기능으로 간주하지 않는다. 효과가 없는 후보는 개발 환경에서만 노출하거나 `enabled: false`로 통제하되, **기존 108개 원본 정의는 삭제하지 않는다.**
- 서버에서 확률, 게임 상태, 이동, 사용 가능 여부를 검증한다.

## 권장 실행 순서

### 0. 기준 상태 확보 및 검증
- 현재 코드, 브랜치, 변경 파일을 확인하고 테스트/타입 검사/빌드를 실행한다.
- 첫 커밋을 만들기 전에 `.env`, API 키, 인증 토큰, 빌드 산출물, 로그, 방 코드 등의 비밀/불필요 파일을 제외하는 `.gitignore`를 점검한다.
- 사용자가 커밋을 승인하지 않았다면 **커밋 자체는 실행하지 말고** 후보 변경 파일과 권장 커밋 메시지만 제시한다.
- 수동 통합 시나리오: 2~4인 입장 → 증강 선택 → 윷 던지기 → 이동/업기/잡기/골인 → 결과 화면을 검증한다.

### 1. 증강 선택 후보 비공개 처리 (최우선)
- 소켓으로 보내는 게임 상태를 **공개 상태와 플레이어별 비공개 상태**로 분리한다.
- 본인에게만 본인의 선택 후보 3장, 리롤 가능 상태를 전송한다.
- 다른 플레이어의 후보/리롤 대상이 네트워크 응답에 포함되지 않도록 한다.
- 재접속·관전자·방장 등 예외에서도 타인 후보가 유출되지 않게 테스트한다.

### 2. 증강 효과 1차 — 패시브 3~4개, 액티브 3~4개
- 기존 108개에서 구현 영향이 작은 증강을 선별하고 **ID/효과/트리거/충돌 규칙을 구현 전에 보고**한다.
- 패시브는 지정한 이벤트 시점에 자동 처리한다. 액티브는 서버에서 사용 조건/남은 횟수/대상/소모 시점을 검증한다.
- 일반 이동·잡기·업기·골인·추가 던지기와의 충돌, 중복 발동, 사용 횟수 초과 테스트를 추가한다.
- 사용 가능한 증강만 실제 드래프트 후보에 넣고 나머지 정의는 비활성화한다(나중에 재활성화 가능).
- 기존 승인 디자인에 있는 사용 가능/소진/사용 불가/예약됨 상태만 구현한다. **액티브 버튼 위치와 대상 선택 방식은 임의 확정 금지**.

### 3. 증강 발동 알림·대전 기록
- 서버가 `사용자 / 증강 ID·이름 / 대상 / 실제 효과 / 결과`를 이벤트 로그로 생성한다.
- 게임 화면의 승인된 알림 바와 대전 기록에 적용한다.
- 상대에게 비공개여야 할 후보 정보는 알림에 노출하지 않는다.

### 4. 대혼란 이벤트 엔진 및 E5·E6
- 전원 정상 턴 4라운드 완료마다 서버가 이벤트를 추첨·발동한다.
- 이벤트와 증강 선택이 겹치면 **이벤트 먼저, 증강 선택 나중**이다.
- 우선 E5(왕의 몰락), E6(전원 출동) 구현 및 테스트 후 다른 이벤트로 확장한다.
- 이벤트 발동 순간, 진행 중 상태, 종료 시점을 서버가 일관되게 관리한다.
- E2(임시 동맹)는 **2~3인 규칙 확정 전 비활성화**, 4인 적용 방식도 별도 검토한다.
- `대혼란 등장.png` 및 승인된 패널 디자인 범위에서만 화면에 반영한다.

### 5. 재접속 복구
- 같은 브라우저에서 새로고침·일시 접속 끊김 후 기존 자리로 복귀하도록 서버 세션/재연결 토큰을 관리한다.
- 사용자 식별/방 소유권을 클라이언트 입력만 믿지 않는다.
- 타이머가 도는 중, 증강 선택 중, 이동 선택 중 재접속 시 상태 복구 테스트를 한다.

### 6. 결과 화면 및 배포
- 실제 보유/사용한 증강을 결과의 ‘함께한 증강’ 영역에 연결한다.
- 2~4인 카드 표시, 승자 1명/패자 나머지 규칙을 검증한다. UI 수정이 필요하면 Figma AI 요청으로만 기록한다.
- GitHub Pages + Render 배포 후 여러 브라우저 동시 접속·HTTPS/WSS·새로고침·타임아웃을 점검한다.

## 유지할 확정 규칙
- 시작 1회 + 전원 2·4·6·8·10라운드 완료 때 1회씩 = 총 6회 획득, 교체 없음.
- 실버 40% / 골드 40% / 프리즘 20%, 선택 회차당 등급은 전원 동일.
- 각 등급 내 대혼란 증강 **그룹 전체 확률** 5%, 일반 95% 분배. 개인 보유/제외 목록에 따라 후보와 확률 재계산.
- 카드별 리롤 기본 1회씩. 단독 꼴찌(골인 말 수가 다른 모든 참가자보다 최소 1개 적은 유일한 사람)는 자유 리롤 1회 추가.
- 정상 턴 행동 18초, 증강 선택 20초, 초과 시 서버 랜덤 자동 진행.
- 첫 4말 골인 플레이어만 승리. 나머지는 패배(결과 표시 정렬과 승패는 구분).

## Claude가 먼저 보고할 사항
1. 현재 코드/테스트 재검증 결과.
2. 1차 증강 후보 6~8개(기존 ID 사용)와 각 구현 난이도·특이사항.
3. 다른 플레이어 증강 후보가 실제로 내려가는 소켓 경로와 보안 수정 대상.
4. 액티브 대상 지정 등에 필요한 **Figma AI 요청 목록**(필요할 때만), 디자인은 생성/수정하지 말 것.
5. 작업 순서별 변경 파일과 테스트 계획.

## Figma AI 요청 목록 (현재 미확정)
- 액티브 증강 사용 버튼의 정확한 배치와 모바일/데스크톱 상태.
- 상대 말·내 말·칸·플레이어를 대상으로 하는 증강의 대상 선택/취소 플로우.
- 활성화/소진/사용 불가/예약됨 상태가 기존 승인 PNG로 충분히 표현 가능한지 확인. 부족한 상태만 추가 요청.

이 문서는 Claude Code의 개발 작업 지시서다. **Figma AI에게 디자인을 변경하라고 직접 실행하는 문서는 아니다.**
